Return the imaginary parts of SamSrf's complex CSS results. With `Css_Convention: "samsrf"`, a negative predicted response (interpolated apertures dip below zero) makes the CSS objective and the betas complex, and MATLAB saves R², nR², Beta and Baseline with their imaginary parts in `Srf.Data`. `Job.merge` now returns those parts as `imaginary`, in the layout of `maps.data`, and `null` when every result is real. A zeroed R² over a negative noise ceiling gives nR² `-0 + 0i`, as in MATLAB. Exported maps still keep only the real parts, as `samsrf_expand_srf` does, and the default `nonnegative` convention is unchanged. The SamSrfAnalysis matrix runners now pass `Css_Convention: "samsrf"` for forward models, because SamSrf always takes complex CSS powers. Against the AMD host of the pinned SamSrfAnalysis source recording, both CSS runs now equal MATLAB in every real and imaginary `Srf.Data` value and every GIfTI, in both precisions (12 to 15 of 21 vertices differed). The Node/WASM matrix there matches 15 of 24 runs and 145 of 168 maps (13 and 129 before), Chromium gives the same bytes, and pull-request CI now holds every map of that matrix to a frozen outcome. Intel hosts, the global-signal sum, geometry, and compiled-container and production-interface parity are still open, and both public single-fit refusals remain.
