# samsrf instructions

- The app reproduces SamSrf X's `SamSrfAnalysis` (samsrf/samsrf@41ed1e96) for GIfTI input: `prf` (forward-model fit), `rc` (reverse-correlation pRF) and `cf` (reverse-correlation connective fields against a template map such as Benson). Numerics belong to `@neurodesk/samsrf`; the app does none.
- `src/engine.js` is the only module that calls the engine: `createJob(inputs)`, `runShard(job, start, end, onProgress)` and `mergeShards(job, shards)`, typed in its header, and `readSurfaceMesh(file)`. A model whose `Hrf` is `hrf_*` names a subject HRF fit; `createJob` reads its `fP` and passes `hrf.oldSchool(TR, fP)` as the job's kernel. `src/pool.js` runs the first three on module workers (`src/worker.js`, one engine instance each, at most 8), shards the ROI's vertices from a queue, merges in the first worker and terminates every worker on cancel. `createJob` reads the inputs with the package's readers (runs through `RunAccumulator`, keeping the ROI and seed vertices), builds the package's `createJob` spec and prepares it once to validate it; every other worker prepares its own copy from that spec on its first shard (for `prf` the search space, about 10 s each), and the first worker merges with `job.merge` and writes the files with `exportGiis`.
- Model presets (`src/models.js`) reproduce the three `Models/Json` examples and the standard `Models/*.m` models; horizontal tuning follows the GUI `.mod` Mu grid and circular tuning fixes scale 1. Only unmodified preset grids regenerate when the radius changes. JSON has no Infinity, so `Hrf` for concurrent fitting travels as the string `"Inf"`.
- A dropped folder is sorted lexically, like MATLAB `dir`, and ambiguous slots or conflicting FreeSurfer/BIDS hemispheres are rejected (`src/inputs.js`): `.label` is the ROI unless its name says seed, a GIfTI named benson/template/atlas is the template, FreeSurfer and `.surf.gii` names are surfaces, other GIfTIs are runs.
- `src/viewer.js` reads each surface on the main thread with `readSurfaceMesh` and draws it from mz3, so it shows the mesh the analysis reads (NiiVue's FreeSurfer reader fails on surfaces without the optional trailing tags, as MATLAB's `write_surf` writes them). Each change of the NiiVue scene starts after the previous one finishes, and a surface load that a later `showSurface` call replaced (Clear inputs, another drop) never becomes the shown surface or reports an error and resolves false; `setInputs` then leaves the status to the newer call.
- Maps are drawn as NiiVue rc.26 mesh layers from scalar-only mz3 (`writeMz3Scalars`). NiiVue draws NaN black and clamps negatives, so `src/display.js` encodes each map: vertices with R² above the threshold map into [1, 2], the rest are 0 and transparent.
- The example (`x001-bars`) uses the original whole-surface X001 runs from HF `samsrf/example-full/`; preserve them because CF uses the whole-surface global signal. The ROI limits fitting; `SAMSRF_EXAMPLE_DIR` serves it locally to the e2e tests.
- The port is `exes/samsrf/core` (the analyses in `fit_prf`, `revcor_prf`, `revcor_cf` behind `job::Job`; MATLAB's `fminsearch` and `samsrf_hookejeeves` in `optim`), `exes/samsrf/wasm` its surface and `packages/samsrf/wasm` the committed module. After a Rust change, follow [the canonical CI build procedure](../../packages/samsrf/README.md#building-the-webassembly-module) to validate and commit the `samsrf-differing-rebuild` artifact from a `wasm_only` dispatch; the ready PR must pass a fresh byte-for-byte rebuild. Everything is f64 where SamSrf is single; `packages/samsrf/README.md` lists every divergence and the options the job refuses (`Smoothed_Coarse_Fit`, vertex-wise HRF files, pRF-from-CF, `Micro_Probing`, `Save_Rmaps`). SamSrf quirks are kept on purpose because they are the numbers: `cf` `Fwhm` indexes `Srf.Area` by seed position, the unsmoothed `Fit_pRF = 1` residual is the N x N broadcast (elementwise once smoothing makes `R` a column), `samsrf_fit2dprf` scales only the first `n - 2` seeds, `samsrf_georoi` puts immediate neighbours at distance 0, and every map is 0 outside the ROI as `samsrf_expand_srf` leaves it.
- The reference is SamSrf's own `.m` code in Octave 9.2 (`packages/samsrf/validation/octave`, Docker, MATLAB-faithful `fminsearch` shim): `parity.mjs` checks readers, preprocessing, HRFs and profiles at 1e-9, `parity-analyses.mjs` the three analyses map by map (`validation/README.md` holds the tables and the single-thread timings). The portable `samsrf` command line (`packages/samsrf/bin`, `release.json`, `validation/cli-check.mjs`) holds every map byte for byte to the in-process job; its `registry/standalone.json` downloads fill in after the first `samsrf-v*` release.
