# General Instructions

- after every change to the source code make sure the Agent.md file is updated
- after every new feature added, make sure there is a test for the feature (no tests for removing features)
- after changing the code, start a new dev server and ask the user to check the resulting app functionality

## Development

- **Start dev server**: `cd web && bash run.sh` (serves on http://localhost:8080)
- `web/run.sh` stops an existing SCT dev server on the requested port before starting a replacement and serves local development files with no-store cache headers; use an alternate port argument when another non-SCT process owns `8080`
- `web/run.sh` uses `ThreadingHTTPServer`; keep it threaded so one idle browser/devtools connection cannot block the whole local server. `npm run test:server` holds an idle TCP connection open and verifies a second request still succeeds.
- **Setup**: `cd web && bash setup.sh` (downloads ONNX Runtime WASM files)

## Linting

Run `npm run lint` before committing JS changes. This parses all `web/**/*.js` files for syntax errors using acorn. The same check runs in CI before deploy.

Common issues it catches:
- `await` in non-async functions
- Mismatched brackets/parens
- Invalid ES module syntax

## Dependency Maintenance

- Keep npm dependencies current with `npm install <package>@latest` so `package.json` and `package-lock.json` stay in sync.
- `web/index.html` loads no viewer code from a CDN. The FreeBrowse/NiiVue versions are pinned in `packages/runtime-support/package.json` (`freebrowse`, `@niivue/niivue`), shared with TopoFit; change them there, then run the SCT and TopoFit e2e suites.

## Architecture

- `web/js/spinalcordtoolbox-app.js` — Main app class, orchestrates everything
- `web/js/app/config.js` — Model config, version (bumped by the manual release workflow)
- `web/js/app/sct-tasks.js` — SCT stable task inventory and task status helpers
- `web/js/app/labels.js` — Task labels + NiiVue label colormap
- `web/js/modules/sct-viewer.js` — `SctViewer`: mounts FreeBrowse and is the one owner of which volumes the viewer shows
- `web/js/app/log-channels.js` — which console log (analysis or technical) a message belongs to, and the run description line
- `web/js/inference-worker.js` runs the 3D inference pipeline as a module worker and uses the shared worker toolkit for routing, model fetches, and common volume operations.
- `web/js/controllers/` contains narrow input-session and pipeline adapters around shared file-IO, DICOM, and `PipelineExecutor` modules.
- `web/js/modules/` — UI components and inference pipeline modules
- `web/js/modules/sct-centerline.js`, `sct-morphometry.js`, `lesion-analysis.js` — ports of SCT 7.3 `get_centerline`, `sct_process_segmentation` and `sct_analyze_lesion`; pure array functions in SCT's RPI layout

## Key Conventions

- The shared example selector is an `nd-example-selector` element returned by `createExampleSelector`. Its upload scope is this app's `.app-container`; append the element directly and retain cancellation before replacement imports.

- Keep the inference worker as an ES module. Add reusable transport, file, and volume behavior to `@neurodesk/webapp-components`; keep SCT model and post-processing policy in the app.
- The viewer is FreeBrowse around NiiVue `1.0.0-rc.13`, mounted with the shared `mountViewer` from `@neurodesk/runtime-support/freebrowse-viewer` (the helper TopoFit uses; design notes in `../../docs/architecture/topofit-surface-inspection.md`). This app has no bundler, so `pnpm runtime-support` (run by `predev`, `prebuild`, `pretest*`) builds that helper into the generated, untracked `web/freebrowse-viewer/index.js`, because `package.json` sets `neurodeskWebapp.static.freebrowseViewer`. `SctViewer` imports it by relative URL; the shared `ViewerController` (NiiVue 0.68 API) is no longer used here. Do not add an app-local copy of the mount helper or a second NiiVue build.
- FreeBrowse owns layout selection, zoom/pan and reset, the intensity window, per-volume opacity, colormap, visibility, image download (its Download dialog writes NIfTI), colorbar/crosshair/interpolation settings, and the Drawing tab. SCT's `.viewer-toolbar` keeps only what FreeBrowse lacks: the Single/Compare mode tabs and the PNG screenshot (`#screenshotViewer`, `nv.saveBitmap`). Do not re-add a duplicate of a FreeBrowse control; `npm run test:ui` rejects the retired ids. Do not hide or disable the Drawing tab.
- Zoom: FreeBrowse's "Right drag: contrast | pan/zoom" toggle sets NiiVue's secondary drag mode; in pan/zoom mode the wheel zooms 2D slices and right-drag pans, in the 3D render the wheel always zooms, and the toolbar reset button restores view and contrast. NiiVue rc.13 has no multi-touch, so the shared helper's `touch-gestures.js` maps a two-finger pinch/drag to the same zoom and pan in any mode. `SpinalCordToolboxApp.VIEWER_HINT` (at most 90 characters, shown in `#viewerInfoPrimary` until the first crosshair readout) tells the user how to zoom, pan and reset. `e2e/viewer.spec.js` covers wheel, right-drag, pinch, two-finger pan and reset in 2D and 3D.
- `init()` starts the viewer mount (`this.viewerReady`) and wires the input listeners in the same tick, so a file chosen before the viewer bundle has loaded is not lost. `renderViewerVolumes()` awaits `viewerReady`, and `onFileLoaded()` sends the volume to the worker without waiting for the display, so a slow or unavailable viewer never delays segmentation. `e2e/viewer.spec.js` covers the early file.
- `app.viewer` is the `SctViewer`, `app.viewerMount` the shared mount handle (`{ nv, ready, showDrawingTools, setDrawingPenValue, destroy }`) and `app.nv` the NiiVue instance; all three are `null` in fallback mode. Later integrations reach NiiVue through these, and must change the volume list only through `SctViewer.showVolumes()`. `SctViewer.showVolumes()` keeps the longest prefix of the stack that is already loaded and as requested, so a volume FreeBrowse added on its own (its Save Drawing) is removed without reloading the base image.
- **Stage data changed** is one event. `app.setStageData(stage, file, { source, manualEdit, labelSetId })` and `app.removeStageData(stage)` are the only ways a result mask changes outside inference; they and `handleStageData()` (source `model`) call `notifyStageDataChanged()`, and consumers subscribe with `app.onStageDataChanged(listener)` (`{ stage, file, source, previousFile, result }`, source `model`, `edit` or `restore`; returns an unsubscribe). `onStageMaskChanged()` is the built-in subscriber: for `edit`/`restore` it refreshes `morphometrySources`, reruns lesion metrics through the existing `run-lesion-metrics` worker route (lesion mask, cord mask when there is one, input image) and remeasures morphometry through `run-morphometry` when its last mask was the changed stage. Model output already carries its metrics and is not measured twice. Do not wire a derived result to edits any other way; `npm run test:manual-edits` and `npm run test:ui` pin the seam.
- Manual edits (issue #9): `web/js/app/manual-edits.js` (`SctManualEdits`, the **Edit masks** section `#editSection`) and `web/js/modules/mask-editor.js` (`MaskEditor`, pure mapping plus the session on NiiVue's drawing layer). FreeBrowse's Drawing tab owns the tools (Draw Mode Pen, Pen Erases, Pen Fill, Undo, Save Drawing); SCT adds only the stage choice (`#editStageSelect`, results plus *New spinal cord mask*/*New lesion mask*), the label by name (`#editLabelSelect`, mirrored into FreeBrowse's Pen Value field), and Apply/Discard/Restore (`#editApply`, `#editDiscard`, `#editRevert`, all secondary). Do not add a second drawing toolbar.
- NiiVue rc.13 holds the drawing as `nv.drawingVolume.img`, a `Uint8Array` in the background volume's RAS voxel order (`dimsRAS[1..3]`, x fastest, the label as the byte). RAS voxel (x, y, z) is native index `img2RASstart[0] + x*img2RASstep[0] + img2RASstart[1] + y*img2RASstep[1] + img2RASstart[2] + z*img2RASstep[2]` of volume 0, which is what NiiVue's own drawing export uses. NiiVue's `loadDrawing` (FreeBrowse's "Edit as drawing") is not its inverse for a permuted orientation: on a 20x14x7 PIR-like image 1192 of 1960 voxels land elsewhere. `MaskEditor` therefore fills the bitmap itself with the inverse map, also when it adopts a layer FreeBrowse opened (Edit as drawing on an SCT overlay, Create empty drawing layer), and reads it back with `drawingToNative`. `e2e/manual-edits.spec.js` proves the round trip voxel-exact on that image, from SCT's Edit mask and from FreeBrowse's Edit as drawing, and pins NiiVue's geometry numbers that `scripts/test_manual_edits.mjs` replays.
- An applied edit is written with the stage file's own header (`buildMaskNifti`: `createNiftiFromData` uint8, scl 1/0, `cal_max` the largest label), so unchanged voxels give back the model file byte for byte; a drawn mask uses the input header, as the worker does. Edited stages are named `<stage file>_edited.nii`, drawn ones `<input>_<stage>_manual.nii`; the result keeps `manualEdit` (`kind` edited/new, `original`, `changedVoxels`, `downloaded`) and the Results row reads *(edited)* or *(drawn)*. Applying with no changed voxel changes nothing. A drawn mask records its `labelSetId`, which `getOverlayLabelTaskId()`/`getOverlayColormapId()` prefer.
- While a stage is on the drawing layer `getViewerStack()` hides its overlay (`manualEdits.isHiding`); the drawing uses the stage's label colormap registered as the NiiVue drawing LUT `_sct_<labelSet>`. During a session `drawIsFillOverwriting` is held true: NiiVue's `addUndoBitmap` merges the previous undo snapshot back into the bitmap at each stroke start when fills do not overwrite, which (from reading the rc.13 source) would bring erased voxels back.
- Unsaved edits (a dirty drawing, or an applied edit not downloaded) are confirmed with `confirm()` before a new segmentation run, a new file or example, a drop, and Clear All. Automation's `segment` passes `runSegmentation({ discardEdits: true })` and logs the discard instead of asking.
- The shared helper's `touch-gestures.js` undoes the pen stroke the first finger of a pinch started in draw mode (detected by `nv.currentDrawUndoBitmap` moving), so a pinch never leaves a dot; `e2e/manual-edits.spec.js` fails without it.
- The app must continue to initialize when the viewer cannot start. `SctViewer.mount()` rejects when the NiiVue canvas attachment rejects (WebGL2 unavailable), when NiiVue resolves without a rendering `backend` (belt-and-braces against a NiiVue that logs-and-returns), or when the viewer bundle cannot be loaded; it destroys the failed FreeBrowse mount first. `setupViewer()` then calls `disableViewer()`. Do not add a separate off-DOM WebGL2 preflight. Keep viewer-only controls disabled through `disableViewer()`/`isViewerAvailable()` in fallback mode, hide `#freebrowseViewer`, and leave file loading, inference, result generation, metrics, and result downloads usable. The viewer-unavailable message (`SpinalCordToolboxApp.VIEWER_UNAVAILABLE_GUIDANCE`, mirrored in the `#viewerUnavailableMessage` static HTML) must name WebGL2 as the cause and the hardware-acceleration/`chrome://gpu` remedy in at most 90 characters, not just say "could not initialize". `npm run test:ui` covers control/source presence, `npm run test:compat` behaviorally exercises the three failure paths → `disableViewer()` plus the actionable message (`scripts/test_viewer_fallback.mjs`), and `e2e/viewer.spec.js` runs the whole app with WebGL2 blocked.
- When the viewer is unavailable, `FallbackNiftiPreview` renders a 2D axial NIfTI slice on `fallbackCanvas2d` using the vendored `nifti-js/index.js` parser. Keep result eye buttons usable in this mode by routing them through `viewStage()`, but do not emulate NiiVue overlay composition in the fallback. `npm run test:ui:modules` covers the fallback decoder/renderer.
- Keep `.viewer-unavailable-message[hidden]` explicitly hidden in CSS. The fallback message is absolutely positioned over the canvas, and the base `.viewer-unavailable-message` display rule otherwise overrides the hidden attribute and paints the error text over a working NiiVue viewer. `npm run test:ui` covers this.
- `web/coi-serviceworker.js` must always resolve fetch events with a `Response`, including third-party analytics/CORS failures, and must reconstruct 204/205/304 responses with a null body. `npm run test:compat` covers the Chrome Response-constructor regressions.
- Route every change of what is displayed through `renderViewerVolumes()`. It is the only caller of `SctViewer.showVolumes()`, and `getViewerStack()` is the only place that computes the requested stack: the base image, then every label-mask stage that has a current result, each with a `visible` flag. Nothing else in the app may call `nv.loadVolumes`/`addVolume`/`removeVolume`; `npm run test:ui` and `npm run test:routing` enforce the single call site.
- Multi-image comparison keeps one active input session for SCT processing while `Compare` view displays loaded input sessions as independent NiiVue canvases for side-by-side review. `SctViewer.showComparison()`/`clearComparison()` own those canvases (NiiVue instances from the same bundle, following the main viewer's layout and drag mode); keep them, `SctInputSessions` session activation, the viewer mode toolbar, and `scripts/test_ui_coverage.cjs` synchronized. Result overlays remain single-session only; `npm run test:viewer`, `npm run test:controllers`, `npm run test:ui` and `e2e/viewer.spec.js` cover the contract.
- Config version is bumped by the manual GitHub Actions release workflow via `sed`; it increments the patch version — do not bump manually
- Keep model availability metadata internal; user-facing UI copy should describe runnable tasks without release/support commentary.
- Keep the Citations modal primary SpinalCordToolbox entry anchored on the De Leener et al. NeuroImage 2017 SCT paper and the stable documentation link.
- There is no SCT Processing section and no `sct_label_vertebrae` port: vertebral and disc labels come from the TotalSpineSeg task (`spine`, stages `spine_step1` and `spine_discs`). Do not reintroduce the C2-C3 HOG/SVM detector, PAM50 level templates, a `processingOnly` task flag or `templateAssets`. The pipeline has four steps, `load`, `inference`, `morphometry` and `lesion_metrics` (the last two measure mask files and depend on no other step); a derived-output feature must add its own step, worker route and real output stage rather than a dropdown of helper operations. `scripts/batch-parity-lib.cjs` classifies the batch script's `sct_label_vertebrae` commands as `not-applicable`, replaced by the `spine` task. `web/js/modules/sct-processing.js` holds pure helpers (image math, MT, DTI, cropping, label utilities) that are unit-tested but not wired to the UI; its centre-of-mass `centerlineFromSegmentation` is not SCT's centerline, use `SCTCenterline.getCenterline` for anything that must match SCT.
- There is no start page: the workspace is the first screen, and the intro lives in the About modal. Status lives in the shared `<footer id="status" class="nd-imaging-status">` (last child of `.app-container`): `#statusText`, `#elapsed`, native `<progress id="progress">` and the hidden `#cancelButton` ×, driven by the shared `ProgressManager`. `beginAbortableStep()` calls `begin()`, step completion calls `end('Complete')`, `onInferenceError()` calls `end(msg, { success: false })` and adds `error` to `#statusText`, and an abort restore resets to `Cancelled`. The footer × is the only abort control. The sidebar has one primary action (`#runSegmentation`). The selected task description lives in the SCT Task info tooltip (`#taskInfoTooltip`); `#taskDetails` shows only the short `Input: …` line. Google Analytics is injected by the monorepo's shared hosting shell, never by `web/index.html`; it sends automatic page views only and makes no Google request when Do Not Track or Global Privacy Control is enabled. If the behavior or privacy copy changes, update `scripts/test_ui_coverage.cjs` in the same change.
- The console below the viewer is the shared `<nd-console id="spinalcordtoolbox-log" collapsed resizable channels="analysis:Analysis,technical:Technical">`; the element builds the toggle, tabs, Copy, Clear and the resize separator, so `web/index.html` holds no console markup and `web/css/styles.css` no console CSS. It starts collapsed; the user enlarges it by dragging its top edge or with Arrow/Page/Home/End on the focused separator (120px minimum, the viewer keeps 160px, size kept while collapsed). An `error`-level line opens it on the log that holds the line.
- A line goes to exactly one log (`web/js/app/log-channels.js`). **Analysis** (`logAnalysis`, worker `postAnalysis`/`postMaskSummary`): loaded input and its dimensions, `Task: … on …` and `Parameters: …` at the start of each run, per-stage result summaries (voxels, mm^3, label count), lesion metrics, TotalSpineSeg and empty-mask warnings, downloads, and run errors/aborts. **Technical** (`updateOutput`, worker `postLog`): worker and ONNX Runtime start-up, model fetch and cache, backend, resampling/reorientation, per-patch statistics, probability-map ranges, timings, viewer loading and example downloads. `routePipelineMessage` sends the shared executor's `Error:`/`Worker error:`/`Aborted …` lines to analysis and the rest to technical; worker lines are technical unless posted with `channel: 'analysis'`. Never write the same line to both, and never put progress in either: status stays in `footer#status`. `npm run test:ui`, `npm run test:ui:modules` and `e2e/console.spec.js` cover the markup, routing, collapse, resize and Copy/Clear.
- User-facing app source links must target `https://github.com/neurodesk/webapps/tree/main/apps/spinalcordtoolbox`; the pre-monorepo repository is import provenance only.
- Run `python scripts/validate_sct_models.py --manifest web/models/manifest.json --all-tasks` after SCT manifest changes
- Large browser model binaries are hosted in Hugging Face dataset `sbollmann/sct-webapp-data` at pinned 40-character revisions, not Git/Git LFS. Keep `downloadUrl`, `checksum`, and `sizeBytes` synchronized across `web/js/app/sct-tasks.js`, `web/models/manifest.json`, and `scripts/hosted-assets.cjs` for standalone hosted assets such as `synthstrip.onnx`; do not reintroduce `.gitattributes` LFS filters for `web/models/*.onnx`. Local copies are ignored cache files and can be materialized with `node scripts/hosted-assets.cjs` or lazily by fixture/worker tests.
- Gray matter (`graymatter`) uses a 2D nnU-Net wrapper with stronger connected-component cleanup; keep its preprocessing (`modelAxisOrder: 'zyx'`) and defaults (`minComponentSize: 1000`) in sync across `web/js/app/sct-tasks.js` AND `web/models/manifest.json` — the runtime reads `sct-tasks.js`, so missing fields there silently disable axis reordering and produce empty/near-empty masks.
- Spinal cord (`spinalcord`) preprocesses every input by reorienting to SCT's `dataset.json` `image_orientation` (`modelOrientation: 'RPI'`) and resampling to `targetSpacing: [0.8958333, 0.7, 1.0]` (RAS xyz mm; the nnUNet `3d_fullres` plan ships `[1.0, 0.7, 0.8958]` in SI/AP/RL order, which matches after the `modelAxisOrder: 'zyx'` transpose) before inference. Without resampling, anisotropic axial inputs (e.g. MT 0.9×0.9×5 mm) feed the wrong physical scale and produce empty masks; keep modelOrientation, targetSpacing, and the zyx axis order synced across `web/js/app/sct-tasks.js` and `web/models/manifest.json`. Runtime defaults must mirror SCT's wrapper: `overlap: 0.5` (`tile_step_size=0.5`), `testTimeAugmentation: false`, `keepLargestComponent: true`, and `minComponentSize: 0`; do not expose a public sliding-window overlap selector. Covered by parity fixtures for the T2, dMRI, T2s, T1, and MT spinal cord cases, plus `npm run test:routing` and `npm run test:inference:postprocessing`.
- Every supported task in the SCT Segmentation dropdown must have a primary model asset; without one `runInference()` would fall back to `Config.MODEL.name` and produce the wrong output. `npm run test:routing` and `npm run test:manifest` enforce the invariant.
- TotalSpineSeg spine labeling (`spine`) is displayed as `TotalSpineSeg` in the SCT task dropdown and uses the Hugging Face-hosted `web/models/totalspineseg-step1.onnx` asset from dataset `sbollmann/sct-webapp-data`, converted from TotalSpineSeg r20251124 Dataset101 step 1 with `scripts/convert_totalspineseg_model.py`. Keep `modelAssets[].downloadUrl` pinned to the HF dataset revision that contains checksum `sha256:22f2e6e0b7a028a80ddd8b211d5c732da8c23a6dbb059fb9d379a67b3f9ce74c`; do not commit this 538 MB ONNX to Git/Git LFS. The browser runs the 9-channel region-sigmoid model, collapses broad/specific channels in nnU-Net `regions_class_order` (`output.labelPriority: [1,2,3,4,5,6,7,8,9]` with strict `> 0.5` thresholding), applies upstream-style largest dilated foreground-component cleanup plus `fill_canal` in `web/js/modules/totalspineseg.js`, maps step-1 labels, and emits visible labelled disc markers (`spine_discs`, `output.discPointRadius: 2`) centered on SCT-style disc points for the `sct_deepseg spine -label-vert 0` output contract. Preserve `preprocessing.modelOrientation: 'RAS'` (upstream uses `nib.as_closest_canonical()` despite its legacy LPI log text), `preprocessing.modelAxisOrder: 'zyx'`, `targetSpacing: [1, 1, 1]`, `output.paddingMode: 'center-min-patch'` (nnU-Net centered padding for short axes), browser-safe `patchSize: [256, 256, 48]`, and the default cleanup dilation of 5 voxels; full plan depth `[256, 256, 96]` is valid in ONNX Runtime Node but exceeds the browser WASM path for this model, while the 48-slice zyx patch lowers per-patch memory and still emits disc landmarks in the worker smoke fixture. The task is exposed with `validationStatus: manual-only` and `browserParityRequired: false`; do not mark it fixture-validated until a real SCT reference fixture is added.
- Keep the `spine` display name synchronized as `TotalSpineSeg` across `web/js/app/sct-tasks.js`, `web/models/manifest.json`, and generator defaults in `scripts/download_sct_models.py`.
- TotalSpineSeg viewer stages are independent label-mask overlays: `spine_step1` uses the `totalspineseg` label set and `sct-totalspineseg` colormap, while `spine_discs` uses the `spineDiscs` label set and `sct-spine-discs` colormap. Both TotalSpineSeg stages must stay `visibleByDefault: true`; `spine_discs` markers must remain inflated enough to be visible in NiiVue rather than single-voxel points. Keep `isOverlayStage()`, `getOverlayColormapId()`, `getOverlayLabelTaskId()`, stage visibility defaults, `Config.STAGE_NAMES`, `web/js/app/sct-tasks.js`, and `web/models/manifest.json` synchronized when changing these stages.
- SCIsegV2 (`lesion_sci_t2`) is a supported multi-output SCT Segmentation task for T2w spinal cord injury images. It is converted from `model_SCIsegV2_r20240729.zip` using `scripts/convert_sciseg_model.py` into hosted asset `web/models/sct-lesion-sci-t2.onnx`; keep the Hugging Face `downloadUrl`, checksum/size, `web/js/app/sct-tasks.js`, and `web/models/manifest.json` synchronized. The source package is region-based (`dataset.json.labels`: `sc: [1, 2]`, `lesion: 2`) with two sigmoid output channels, not a background/sc/lesion softmax model. Preserve `preprocessing.modelOrientation: 'RPI'`, `modelAxisOrder: 'zyx'`, `targetSpacing: [0.6875, 0.5077999234199524, 0.68751]`, `patchSize: [128, 192, 96]`, `output.activation: 'sigmoid-regions'`, and the region-to-stage mapping.
- `lesion_sci_t2` emits three stages from one inference run: `segmentation` (`_sc_seg` spinal-cord mask), `lesion` (`_lesion_seg` SCI lesion mask), and `lesion_metrics` (CSV/table metrics). The worker must split masks by the asset `output.regions` metadata and must not hard-code SCIseg numeric channels outside the manifest/task metadata.
- MS lesion (`lesion_ms`) is converted but not enabled: `scripts/convert_ms_lesion_model.py` turns fold 1 of SCT's five-fold model (release `r20250909`, what `sct_deepseg lesion_ms -single-fold` runs in SCT 7.3) into a 409 MB ONNX whose single output channel is `logit(lesion) - logit(background)`. The task stays `unsupported` with no `modelAssets` until that file is hosted in `sbollmann/sct-webapp-data`; a declared `downloadUrl` that returns 404 would break `scripts/hosted-assets.cjs`, the deploy asset check and the fixture gates.
- The region pipeline (`runRegionInferencePipeline`) takes two opt-in asset options for such a model: `output.paddingMode: 'center-min-patch'` (nnU-Net's centred padding of axes shorter than the patch) and `output.gaussianSigmaScale` (a Gaussian whose sigma is a fraction of each patch dimension, 0.125 in nnU-Net, instead of the fixed 8 voxels). `lesion_sci_t2` sets neither and keeps its validated behaviour.
- A region asset without a cord region opts in to metrics with `output.metricsStage`. `analyzeLesions()` then runs without `spinalCord` (`analyzeLesionsWithoutCord`): SCT's `sct_analyze_lesion -m` without `-s` measures the volume only, and the app adds length, width and equivalent diameter without angle correction (there is no cord to take angles from). The cord-relative columns (axial damage ratio, midsagittal, tissue bridges; `CORD_RELATIVE_COLUMNS`) are left out of the CSV, as in SCT, and the Results table shows only the columns the CSV has. The parity case `fake_lesion_no_cord` pins the volume against SCT and checks the three added columns are present. Do not synthesize a cord mask to fill them.
- Lesion metrics live in `web/js/modules/lesion-analysis.js`, a method-by-method port of SCT 7.3 `sct_analyze_lesion -m lesion -s cord -i image`: lesions are labelled on the whole mask with 18-connectivity (`skimage.measure.label(connectivity=2)`, numbered in NumPy scan order of the RPI array), then restricted to the cord; length, width, equivalent diameter and bridges are corrected by cord angles from the centerline fitted over every slice (`minmax=False`, smooth 20); the midsagittal slice is the mean cord centre over five slices around the largest lesion; bridges are interpolated between the two sagittal slices around it, with the cord AP diameter as fallback for a parasagittal lesion. The CSV has the columns of SCT's `measures` sheet in SCT's order (`label`, `volume [mm3]`, …, `slice_N_*_bridge_width [mm]`), sagittal slice numbers in the stored orientation, bridge ratios in percent of the total bridge. `-f`, `-perslice`, `-nli-slice` and QC are not ported. `emitLesionMetrics({ lesionRAS, cordRAS, imageRAS, … })` in the worker is the one entry point: inference calls it with the task's masks, and the `run-lesion-metrics` route (`SctPipeline.runLesionMetrics`, automation operation `lesion-metrics`) calls it with lesion, cord and optional image NIfTI files, so masks from another task or from manual editing are measured by the same code. `e2e/lesion-metrics.spec.js` runs that route on SCT's fake-lesion masks and checks every number against the SCT reference. Results with `stageData.kind === 'metrics'` are CSV/table data, not NIfTI overlays, and must be excluded from the Results image-layer list (`stageButtons`). Each metrics stage renders as its own `[data-metrics-stage]` block in `metricsResults` with a CSV download button; viewing an image stage must not clear them.
- Morphometry (`web/js/modules/sct-morphometry.js`) is a port of SCT 7.3 `sct_process_segmentation`: `computeShape` is `compute_shape`/`_properties2d` (angle correction by `skimage.transform.warp` scaling, 0.1 mm `scipy.ndimage.zoom`, `regionprops` second moments, convex-hull solidity, AP diameter averaged over 3 mm of the rotated mask), `aggregateMetrics`/`toCsv` are `aggregate_slicewise` including the CSV column layout, quoting, CRLF and Python float formatting, and `levelsFromDiscs` is the `-discfile` path (`project_centerline` then `label_regions_from_reference`). Not ported: `-anat` metrics (HOG angle, quadrants, symmetry), `-pmj`, `-normalize`, `-normalize-PAM50`, `-centerline`, other centerline fits, QC.
- Everything that must match SCT runs in SCT's RPI layout (x right to left; `SCTCenterline.rasToRpi` flips x of a RAS volume) and with SCT's voxel sizes (`sctSpacing`: float32 pixdims rounded to float32 precision, so 0.800000011920929 is 0.8; without it angles drift by 1e-7 degrees). SCT rounds and reports some coordinates in the stored orientation, so pass `nativeFlips` (`nativeFlipsFromRas(flip)`) to `levelsFromDiscs` and `analyzeLesions`.
- `sct-centerline.js` contains a port of FITPACK `curfit`/`fpcurf`/`splev`/`splder` (1-based arrays, as in the Fortran) because SciPy's `splrep(s=…)` is what SCT's B-spline centerline calls. It reproduces SciPy's knots, coefficients and derivatives; `scripts/test_sct_morphometry.cjs` pins that against `test/fixtures/sct-metrics/scipy_splrep.json`. Do not replace it with another smoothing spline: every angle-corrected number depends on it.
- Parity with real SCT is the acceptance test for both metric modules. `test/fixtures/sct-metrics/*.csv` are written by the real tools in the pinned container (`scripts/generate_sct_metric_references.cjs`, `npm run test:metrics:references`, needs Docker); `cases.json` lists the runs for the generator and for `scripts/test_sct_metrics_parity.cjs`, which compares every cell (columns, order, empty cells, quoting, numbers within 1e-9; measured agreement is better than 1e-11). A change that alters a number needs a regenerated reference showing SCT does the same; do not widen the tolerance. A known, documented choice: equal-distance ties in the disc projection go to the disc's own slice (SCT leaves them to floating-point rounding of the affine).
- The Morphometry section (`#morphometrySection`, secondary button `#runMorphometry`) measures a mask already in the session without inference. `this.morphometrySources` remembers, for the current image, the `segmentation` mask of the last task and the TotalSpineSeg `spine_step1` cord (label 1) as masks and `spine_discs` as disc labels; they survive a new segmentation run (so a cord mask and TotalSpineSeg discs from two runs can be combined) and are dropped by a new file and by Clear All. Mask and disc labels are separate, visible selects; discs are selected when they appear and the result names both inputs. The page sends the chosen NIfTI files to the worker route `run-morphometry`, which does not use the loaded image, so the same route measures edited or uploaded masks. `automation.json` exposes it as operation `morphometry` (inputs `segmentation`, optional `discs`). `e2e/morphometry.spec.js` drives both and checks the numbers against the SCT references.
- Metric summaries go to the analysis log through the worker's `postAnalysis` (lines starting `Morphometry:` and `Lesion metrics:`, warnings at level `warning`); per-patch and file details stay in the technical log (`postLog`).
- Label-mask stages (`segmentation`, `lesion`, `spine_step1`, `spine_discs`) have independent Results visibility tracked in `_stageVisibility`; the Results eye buttons must only toggle their own stage. Label masks are overlays above the base image in stable order (`segmentation`, `lesion`, `spine_step1`, then `spine_discs`). Visibility, the input's included, is NiiVue opacity on the loaded volume: hiding the input sets volume 0 to opacity 0 and keeps it loaded, so nothing is promoted or reordered. FreeBrowse's own eye, opacity slider and delete button report back through `onViewerStageVisibility()`, and `SctViewer` remembers the opacity the user chose per stage (default `DEFAULT_OVERLAY_OPACITY` 0.7). Adding a new label-mask stage means: extend `isOverlayStage()`, map it in `getOverlayColormapId()` and `getOverlayLabelTaskId()`, and include it in the stable overlay order used by `getVisibleOverlayStages()` and `getOverlayStagesWithResults()`.
- `SctViewer.showVolumes()` applies requests in order and reloads only from the first entry that changed: an unchanged stack makes no NiiVue call, an eye toggle is one `setVolume(index, { opacity })`, a new result adds its overlay without reloading the input, and only a different base file calls `nv.loadVolumes`. That is what keeps the user's zoom, pan, layout and intensity window across results. Entries are matched by `File` identity, stage and `colormapKey`; volumes the user loaded or deleted through FreeBrowse are detected by NiiVue volume id and trigger a rebuild. `npm run test:viewer` pins the call sequences.
- `File` objects are handed to NiiVue directly (`{ url: file, name }`); there are no object URLs to keep alive or revoke.
- `renderViewerVolumes()` serializes renders on `_renderViewerPromise` so repeated stage updates (`segmentation`, `lesion`, `lesion_metrics`) collapse into ordered `showVolumes()` calls. `npm run test:viewer` and `npm run test:routing` enforce this.
- Visible label-mask stages MUST also have a current result before rendering; never auto-render a stale sibling result whose stage is missing from the current run. Whenever a new run starts (`runSegmentation`, `clearResults`, `resetAllSteps`), call `resetStageVisibility()` and re-render so the viewer cannot show a previous overlay. `npm run test:routing` enforces these invariants.
- Label-mask NIfTI outputs must preserve the true maximum label value in `cal_max`. In the viewer, label colours come from the label colormap, which is indexed by label value and does not depend on `cal_max`.
- Worker VM harnesses (`scripts/test_inference_worker_e2e.cjs`, `scripts/test_inference_worker_protocol.cjs`) must evaluate every local worker module imported by `web/js/inference-worker.js` (`inference-pipeline`, `sct-centerline`, `lesion-analysis`, `sct-morphometry`, `totalspineseg`) and promote each UMD export onto the sandbox global. Worker e2e settings must mirror app settings (`threshold`, `preprocessing`, and `output` from the selected model asset); using stale names such as `probabilityThreshold` hides browser-only integration failures.
- Keep the worker's legacy `run` message path semantically aligned with `run-inference`; it must forward `threshold`, `preprocessing`, and `output` so tests and older callers exercise the same activation/post-processing branches as the app.
- `generateLabelColormap()` in `web/js/app/labels.js` returns the colormap for NiiVue 1.0's `nv.setColormapLabel(volumeIndex, colormap)`: one entry per label with `I` holding the raw label value (not a 0..255 ramp), plus `labels` names. NiiVue builds an index-addressed table from it, samples it nearest-neighbour (neighbouring labels never blend), shows the names in its legend, and reports them in location events. Label 0 must be present and transparent because the table starts at the lowest index. NiiVue clamps `I` in place, so every call returns fresh arrays and `SctViewer` passes a copy. `npm run test:labels` enforces this. Use perceptually-ordered palettes (turbo-style) for ordinal label sets like disc levels — neighbouring labels get neighbouring hues, which reads the anatomy correctly.
- UI control coverage is enforced by `npm run test:ui`; browser-generated fixture parity for critical supported tasks is enforced by `npm run test:fixtures`. Regenerate fixture outputs with `npm run test:fixtures:generate` when model preprocessing changes.
- SCT batch reference fixtures are downloaded from Hugging Face dataset `sbollmann/sct-webapp-data` by `scripts/huggingface-fixtures.cjs`; the SCIseg fake-lesion fixture is downloaded from `spinalcordtoolbox/sct_testing_data`. Only `input.nii.gz`, SCT reference outputs, and `batch_processing.sh` are downloaded. Browser outputs remain locally generated by `npm run test:fixtures:generate`. Keep transient HTTP retry behavior covered by `npm run test:downloads` so a brief CDN 429/5xx response does not fail the full suite.

## CI/CD

- **Release workflow** (`../../.github/workflows/release.yml`): manual-only promotion that uses the registry-declared `test:release` gate for this app, then creates the release tag and GitHub release. Generated SCT batch parity and real worker inference remain outside routine releases.
- **Full Test Suite workflow** (`../../.github/workflows/sct-full-tests.yml`): independent manual/nightly workflow with a 240-minute job budget. It runs the full `npm test` suite, uploads its log, and summarizes failures. `SCT_WORKER_TIMEOUT_MINUTES` sets the per-volume inference watchdog, defaulting to 30 minutes. Routine CI uses the registry-declared `test:release`; the full suite is not a dependency of release or deployment.
- **Deploy workflow** (`.github/workflows/deploy-pages.yml`): deploys staging from `main` immediately on pushes to `main`, and deploys production from the latest release tag after the manual release workflow completes successfully. It downloads ONNX Runtime WASM files and verifies model assets before deploying to GitHub Pages; tests are run by the manual Full Test Suite workflow, not by release or deploy.
- GitHub Pages deploys must verify hosted `downloadUrl` assets by pinned URL and still tolerate older release tags that contain local Git LFS assets by checking any local `web/models/*.onnx` or template `.nii.gz` files are real binaries, not pointer files.
- Production deploys build from the latest release tag while the workflow file comes from `main`; asset verification must tolerate older release tags by validating ONNX files and template `.nii.gz` files that exist in the checked-out build, without hard-coding newer template paths.
