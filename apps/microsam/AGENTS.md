# microsam instructions

- Interactive 2D and 3D Z-stack segmentation with micro-sam's `vit_t_lm` (light microscopy, `faithful-chicken`) and `vit_t_em_organelles` (electron microscopy organelles, `greedy-whale`, both CC BY 4.0) pinned in `models/microsam.manifest.json`: the encoder runs once per slice (WebGPU, else WebAssembly) and caches per-slice embeddings in one worker per image/model/channel (`src/worker.js`) that is terminated to cancel; the decoder runs once per prompt change (WebAssembly). 3D Z-stacks (OME-TIFF and ImageJ TIFF) propagate a seeded slice bidirectionally by bounding-box projection (`boxFromMask` + `iouThreshold`), matching `micro_sam.v1.multi_dimensional_segmentation.segment_mask_in_volume`, and export a multi-page 3D label TIFF and 3D CSV table.
- `src/preprocess.js` reproduces micro-sam's `_to_image` and SAM's resize, including a port of Pillow's bilinear `Resample.c`; `test/preprocess.test.js` holds the uint8 image, the resize and the encoder tensor to micro-sam's SHA-256 (`validation/preprocess_reference.py`). Change them together.
- Export the models as `micro_sam.util.get_sam_model` returns them, without `eval()` and with `TrainingMode.PRESERVE` (`validation/export_onnx.py` asserts the zero cache, `cached_attention_bias_absmax: 0` in the manifest): `train(False)` refreshes TinyViT's cached attention biases from the trained ones, and the export would no longer give micro-sam's masks. Upstream disagrees with itself: MobileSAM's `build_sam_vit_t` calls `eval()` before loading and `get_sam_model` loads after building, so inference has the zero cache, while `SamTrainer` validates and the BioImage.IO export runs with live biases. The deciding evidence is that `faithful-chicken` 1.1's published test embedding matches the zero-cache state; annotation IoUs on the example are in-sample (BBBC038 stage1_train is generalist training data) and are no evidence. An upstream micro-sam issue should be filed; until it is answered keep the zero cache, which the NOTICE, manifest and HF README state as a modification.
- `e2e/workflow.spec.js` requires the 24 masks of `validation/reference.json` (micro-sam's PyTorch outputs) byte for byte in the browser; rerecord with `validation/reference.py` after changing the model, the prompts' handling or the example. The hashes are pinned to `onnxruntime-web` 1.29.0: some pixels lie within 3.9e-5 of the threshold against 6.2e-4 export error. On an ONNX Runtime bump, if a hash changes, take the differing pixels from the browser and from `reference.json`, check each against micro-sam's PyTorch mask logits and accept only pixels whose logit is within the export error of 0; then re-record the hashes. Any other differing pixel is a regression. `segment_from_*` takes no `return_logits`: in `validation/reference.py`'s environment, repeat what the case's `segment_from_*` function in micro-sam's `prompt_based_segmentation.py` does (set the precomputed embedding, convert the prompt to the predictor's coordinates, pick the same mask), but call `predictor.predict(..., return_logits=True)` and compare the returned full-resolution logits.
